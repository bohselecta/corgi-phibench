# PhiBench v0.1.0 public release contract

For researchers and developers comparing coding-agent control policies, PhiBench
makes a matched experiment inspectable: the same tasks, provider, evaluator and
resource ceilings, with actual receipt replay showing pacing, context and recovery.
It is an apparatus release. Real-model comparative evidence and interoperability
are NOT RUN; no policy superiority or token-productivity claim is made.

The release includes the existing Python execution/security kernel, six versioned
policies, independent final evaluator, frozen experiment manifests, durable receipts,
rollback/interruption recovery, bounded custom task/method interfaces and an offline
laboratory with matrix metrics, time travel, frontier inspection, context-byte
composition, saved code/patches/full-file lineage and MDL validation/download.
Success, null, regression and split/recovery fixtures remain separately labeled.

Viewing the retained HTML needs a modern browser. Export/replay uses Python 3.11+
on POSIX. New execution is supported on Linux x86_64 with Bubblewrap 0.12.0+,
prlimit, distribution Python and permitted user namespaces/seccomp. CI tests harness
Python 3.11–3.14. macOS/Windows execution and ARM64 are unverified. The Python package
has zero runtime package dependencies; Node/Playwright are development tools only.

No original private code, Git history, holdouts, historical empirical data or
proprietary media is distributed. Source ideas and authorship remain attributed;
Apache-2.0 and NOTICE are retained from the existing public pilot. Generated fixtures
know the answers and do not obey frontiers. Actual provider calls need explicit
runtime authorization and positive ceilings; this recovery's paid budget is $0.

Bounded tools mediate persistent edits; code executes in an isolated read-only
workspace. The builder cannot alter the trusted oracle. Unsupported environments
and malformed/corrupted evidence fail closed. Journal integrity is not signed
attestation or causal authorship. Unknown usage remains unknown. Exports run no
candidate code and make no requests. Existing experiments are never overwritten.

The [detailed acceptance and release plan](docs/RELEASE-CONTRACT.md) fixes the
README golden journeys, technical/product/design checks and exact wheel/sdist/checksum
identities. The [preservation inventory](docs/PRODUCT-PRESERVATION.md) binds source
surfaces to public outcomes. Human approval binds one clean SHA/tree before main,
tag and Release publication; fresh public verification and metadata then close the
release. Registry upload, paid providers and company-site publication are excluded.
